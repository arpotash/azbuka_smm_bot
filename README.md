# azbuka_ssm — бот для ведения Telegram-канала

Бот напоминает менеджерам о посте по тематическому расписанию, сам предлагает варианты (товар с сайта, акция, статья блога, новость из RSS), собирает материал (текст, фото, ссылку), через Claude готовит черновик, показывает превью и по кнопке публикует в канал. Канал: интернет-магазин «Азбука Леса» (as-lesa.ru), отделочные материалы из дерева и всё для бани.

Инструкция для менеджеров и администратора, без технических деталей: [USAGE.md](USAGE.md).

## Как это работает

```
пн 12:00 поставки/акции ─┐
ср 12:00 товар           ├─► напоминание с темой и 3 вариантами от бота
пт 12:00 новости         ┘        [Взять 1] [Взять 2] [Взять 3] [Другие варианты] [Пропустить]
                                              │
                    менеджер жмёт «Взять N» или шлёт свой текст/фото
                                              │
                                модель задаёт вопрос ◄─┐ (пока данных мало)
                                              ▼        │
                                     превью поста ─────┘
                              [Опубликовать] [Правки] [Пропустить]
                                              │
                                     пост в канале, запись в БД
```

Откуда берутся варианты:

| Тема | Источник | Как выбирается |
|---|---|---|
| `promo` | акционные товары сайта (`is_promoted`) | все, что есть; если акций нет, бот честно пишет об этом |
| `product` | весь каталог сайта, 6780 товаров | случайная категория → случайная страница → случайный товар с фото, ценой и остатком |
| `news` | статьи блога сайта + RSS-ленты из `NEWS_FEEDS` | минимум одна статья блога, остальное свежие новости за `NEWS_MAX_AGE_DAYS` |

Защита от повторов: выбранный товар не предлагается 180 дней, показанный и не выбранный 30 дней, категория выбранного товара 45 дней (варианты одной вагонки разной длины не пойдут подряд). Использованные статьи и новости не повторяются никогда. Сроки настраиваются в `.env`.

Сайт отдаёт данные через открытый JSON API (`/api/product/…`, `/api/blog/…`), поэтому каталог не индексируется и не зеркалится: бот делает несколько запросов в момент напоминания. Все обращения в [site_api.py](app/services/site_api.py); если API недоступен, приходит обычное напоминание без вариантов.

Статусы поста: `reminder → collecting → drafting ⇄ revision → published | skipped`. Одновременно в работе один пост. Если к следующему напоминанию пост не закрыт, он помечается пропущенным.

Что бот проверяет сам, не доверяя модели:
- лимит подписи 1024 символа (4096 без фото), при превышении просит модель сократить, иначе шлёт фото и текст отдельно;
- валидность Telegram-HTML, при ошибке просит исправить, иначе публикует без разметки;
- белый список менеджеров;
- последние посты для контекста берёт из своей БД.

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Добавьте бота администратором канала с правом «Публикация сообщений».
3. Узнайте id канала: перешлите любой пост канала боту [@userinfobot](https://t.me/userinfobot) или посмотрите `chat.id` в логах. Для каналов это число вида `-100…`.
4. Узнайте `user_id` менеджеров (тот же @userinfobot).
5. Скопируйте `.env.example` в `.env` и заполните.
6. Запустите:

```bash
docker compose up -d --build
docker compose logs -f
```

7. Каждый менеджер один раз пишет боту `/start`. Без этого Telegram не даст боту отправить напоминание.
8. Администратор шлёт `/llmtest`, чтобы проверить доступ к модели, и `/new`, чтобы открыть тестовый пост вне расписания.

### Без Docker

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
cp .env.example .env   # и заполнить
.venv/bin/python -m app.main
```

Пример systemd-юнита:

```ini
[Unit]
Description=azbuka_ssm telegram bot
After=network-online.target

[Service]
WorkingDirectory=/opt/azbuka_ssm
EnvironmentFile=/opt/azbuka_ssm/.env
ExecStart=/opt/azbuka_ssm/.venv/bin/python -m app.main
Restart=always
RestartSec=5
User=bot

[Install]
WantedBy=multi-user.target
```

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/start`, `/help` | менеджер | справка, регистрация диалога с ботом |
| `/status` | менеджер | текущий пост, статус, кто ведёт |
| `/cancel` | менеджер | отменить текущий пост |
| `/new [тема]` | админ | закрыть текущий пост и открыть новый вручную; `/new product`, `/new promo`, `/new news`, без аргумента без темы |
| `/llmtest` | админ | проверить связь с моделью |

Материал можно присылать и без напоминания: любое сообщение с текстом или фото открывает пост. Свободный текст после превью считается правками, кнопку «Правки» нажимать не обязательно.

## Доступ к модели

Anthropic API официально не работает из России. Бот ходит через прокси или провайдера с совместимым Messages API: укажите его адрес в `ANTHROPIC_BASE_URL`. Если прокси отклоняет необязательные поля запроса:

- `LLM_PROMPT_CACHE=false` убирает `cache_control`;
- `LLM_EFFORT=` (пусто) не отправляет `output_config`;
- `LLM_SERVER_FALLBACK=false` (по умолчанию) не использует beta-заголовки.

Модель задаётся в `ANTHROPIC_MODEL`, по умолчанию `claude-opus-5`.

Проверенная конфигурация для OpenRouter (ключ `sk-or-…` кладётся в `ANTHROPIC_API_KEY`):

```env
ANTHROPIC_BASE_URL=https://openrouter.ai/api
ANTHROPIC_MODEL=anthropic/claude-opus-5
```

OpenRouter принимает `cache_control` и изображения в base64, поэтому `LLM_PROMPT_CACHE=true` можно оставить.

## Расписание и темы

```env
SCHEDULE_PLAN=mon 12:00 promo; wed 12:00 product; fri 12:00 news
```

Формат записи: `день время тема`, записи через `;`. Дни `mon…sun`, темы `promo`, `product`, `news`, `free`. Записей может быть сколько угодно, в том числе несколько в день. Тема попадает в напоминание менеджеру и в системный контекст модели. Тексты тем и подсказки модели по каждой теме лежат в [themes.py](app/themes.py).

## Промпт

Системный промпт лежит в [prompts/system.md](prompts/system.md). Контракт с моделью: либо текст вопроса, либо ровно один блок `<post>…</post>` с Telegram-HTML. Переход в состояние «черновик готов» бот определяет по наличию тега. Голос канала, правило «вопрос или пост», лимиты и режим правок описаны там же, менять можно без правок кода.

Динамическая часть (дата и последние посты) добавляется отдельным блоком, статическая часть кэшируется.

## Проверка без Telegram и без API

```bash
.venv/bin/python -m pytest -q
```

Тесты покрывают валидатор HTML, парсинг ответа модели с ретраями и фолбэками, публикатор (подпись, медиагруппа, split, plain) и сквозной сценарий слота на заглушках бота и модели.

Для ручной проверки бота без ключа модели: `LLM_PROVIDER=fake` и `LLM_FAKE_REPLY_FILE=/path/reply.txt`. Бот будет отдавать содержимое файла как ответ модели: положите туда вопрос или `<post>…</post>`, чтобы прогнать любой сценарий.

## Данные

SQLite в `DATA_DIR/bot.db` (в Docker это volume `./data`), кэш фото в `DATA_DIR/media`. Таблицы: `slots`, `slot_messages` (вся переписка по посту, включая ответы модели), `posts`.

## Что не входит

Несколько каналов, веб-админка, статистика, удаление отдельного фото из набора (только `/cancel` и новый пост), поиск новостей через веб-поиск модели (используются RSS-ленты).
